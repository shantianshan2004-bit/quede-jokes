# 缺德笑话

给损友共享聊天截图的图墙。上传截图，自动归类、打标签，然后点赞和吐槽。

> 一个单文件网页应用：零依赖、零构建、双击就跑。

---

## 这是什么

朋友们之间最好笑的东西往往散在各自的聊天记录里，翻不到、留不住。这个网站把这些截图收在一个地方，并且**自动读懂它们**——识别属于哪一类、起了什么标题、有哪些标签、谁在说话、是不是群聊、是不是长截图。

跟普通网盘相册的区别在于：归档、评论、点赞这些都是围绕"聊天截图"这件事设计的。

## 现在能做什么

**进门**：起昵称、挑头像（10 个 emoji 预设，或上传自己的图，自动裁成方形压到 160px）。右上角常驻你的头像。

**收图**：点选、拖拽、或者直接把截图 `Ctrl+V` 粘贴进来，支持一次多张。带完整的归档流水线动画，四个阶段（读取图像 → 提取文字 → 理解归类 → 归入图墙）显示的都是真实算出来的结果。

**自动归档**：6 个分类加一个「待归类」兜底。分类、标题、标签、发言人、情绪、群聊判定、长截图判定全部是本地算的。判断依据会明确列出来（命中了哪几个关键词），备选分类也会告诉你。**分类可以人工推翻**——详情页里七个分类直接点，改过会标上「人工」。

**图墙**：不规则瀑布流，可以搜索、按分类筛选，内容全出血顶到屏幕边。

**互动**：点开放大看原图，点赞（有飘心动效），评论区长成了聊天气泡的样子——因为分享的内容本来就是聊天。

**个人主页**：头像、签名、四项统计（我传的 / 收到的赞 / 我发的评论 / 在这儿的第几天），三个标签页：我传的、我评论的、账号设置。署名靠**身份 ID** 关联而不是靠名字，所以改名之后历史截图和评论的署名会一起更新。

**视觉与动效**：液态玻璃（Liquid Glass）材料语言 + 全程非线性动画。玻璃只出现在导航和功能层，内容层保持不透明——这是 Apple 规范里明确要求的，玻璃叠玻璃会让层级烂掉。

## 怎么跑起来

### 方式一：双击 `start-server.bat`（推荐）

会启动一个本地服务并自动打开页面。**只有这种方式，你上传的图和评论才会被保存下来。**

### 方式二：直接双击 `index.html`

能看、能玩，但关掉页面数据就没了。

### 方式三：自己起服务

```bash
python -m http.server 8787
# 然后打开 http://localhost:8787/
```

### 为什么必须走本地服务

浏览器对 `file://` 协议禁用了 IndexedDB。直接双击打开时，数据只能退化成存在内存里，一关就消失。这不是 bug，是浏览器的安全限制。

## 上传到 GitHub

仓库名 `quede-jokes`，公开。这个文件夹已经是一个 git 仓库，并且已经有提交记录，只差把它推到 GitHub。

### 第一次推送

1. 打开 github.com，右上角 `+` → `New repository`
2. 仓库名填 `quede-jokes`，类型选 `Public`
3. **不要**勾选 `Add a README file`、`.gitignore`、`license`——留空仓

   > 这一步很关键。如果远端先有了 README，它和本地就是两条不同的历史，push 会被拒绝。
4. 建好后回到这个文件夹，**双击 `push-to-github.bat`**
5. 第一次会弹出浏览器让你登录 GitHub。授权之后，推送会自动接着跑完

脚本第一次运行时会让你粘贴仓库地址，形如：

```
https://github.com/你的用户名/quede-jokes.git
```

不想用脚本的话，手动就这三条命令：

```bash
git remote add origin https://github.com/你的用户名/quede-jokes.git
git branch -M main
git push -u origin main
```

### 以后每次改完

```bash
git add -A
git commit -m "说明这次改了什么"
git push
```

### 打开在线预览（免费）

仓库页面 → `Settings` → 左侧 `Pages` → Source 选 `Deploy from a branch`，
分支选 `main`、目录选 `/ (root)` → `Save`。

等一两分钟，网址就是：

```
https://你的用户名.github.io/quede-jokes/
```

> 注意：这给的只是**别人能看见界面**。页面是纯前端，数据存在各自的浏览器里，
> 朋友之间仍然看不到彼此的图。真正的共享要等接上后端。

## 技术说明

- **单文件、零依赖、零构建**：所有 HTML / CSS / JS 都在这一个文件里，图片没有外部素材，示例截图由 canvas 当场画出来。
- **数据存在浏览器本地**：IndexedDB 存图片（dataURL），降级时用 localStorage。所以数据只属于你这台设备。
- **自动归档是本地规则引擎**，不是 AI：靠关键词、标点、长度、尺寸这些特征打分。它读不出纯靠语气的笑点——这是方法本身的边界，详见「已知限制」。
- **动效**：Web Animations API + CSS。主干曲线 `cubic-bezier(0.34,1.56,0.64,1)` 的凝胶回弹，全程可中断。
- **环境光**：页面的背景色是从你上传的截图里真实提取的主色，玻璃会跟着内容变色。

## 已知限制

1. **还只是单机版**。数据存在你自己的浏览器里，朋友之间目前看不到彼此的图。要真正共享，需要接后端。
2. **登录是本地身份，不是真账号**。门卡底部把这件事原样写给了访客。换设备或清浏览器数据，身份就没了。
3. **归档读不出梗**。关键词分类有天花板：一句笑点全靠语气、全篇一个梗词都没有的对话，引擎只能按字面归类。
4. **图片很吃空间**。浏览器本地存储有容量上限，别几十张原图连着传。

## 隐私提醒

聊天截图常常带着别人的名字、头像和不该外传的话。建议：

- 发之前先给涉及他人的部分打码
- **不要把真实聊天截图提交进这个仓库**（`.gitignore` 里已经预留了排除规则）
- 仓库里只有代码，没有数据
